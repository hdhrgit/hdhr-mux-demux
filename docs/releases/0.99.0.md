## hdhr-mux 0.99.0

A virtual HDHomeRun that combines several physical HDHomeRun devices into one, and shares a tuner between everybody watching the same channel.

**What it does**
- Presents one device with all your tuners (stable numbering, strict 1:1 with the physical tuners) and speaks the HDHomeRun protocols: discovery, control, HTTP API, `/auto/` streams, SSDP/DLNA, lineup and scan.
- `/auto/` viewers (Channels DVR, the playlist, DLNA) of the same RF channel share one physical tuner; only the programmes being watched (plus the guide) are pulled from the device. ATSC 3.0 services are handled, and ATSC 1.0 streams avoid the 3.0-capable tuners. Clients that ask for a tuner by number or over the control protocol (tvheadend, `hdhomerun_config`) get exactly that tuner, as on a real HomeRun; `/auto/` may join them (`auto_join_direct`), and their idle guide scans give way when a viewer needs a tuner (`evict_scans`).
- Channel list from the devices' own lineups; programme guide (XMLTV on `/epg`) collected from the broadcasts' PSIP; M3U/M3U8 playlist on `/playlist.m3u8` (SD channels marked for Channels DVR) for players that cannot use HDHomeRun. A rescan from Channels DVR is handed to one idle device's own scan.
- Web interface on `/ui/`: live activity (who watches what, programme now/next, signal, which tuner another application holds), lineup, **settings** (saved to the state directory, with a warning when that directory would not survive a container), light/dark/system themes. Prometheus metrics on `/metrics`.
- Pulls from the devices over HTTP, so it works in Docker without publishing UDP ports.
- Streams leave with an IP TTL of 3, like the devices' (`stream_ttl`, never more than 8), and a UDP/RTP target must be on a private IPv4 network: it is not meant for use across the internet. Use a VPN for remote viewing.

**Install** (see the README)
- Docker: `ghcr.io/hdhrgit/hdhr-mux` for linux/amd64, linux/arm64 and linux/arm/v7 (Raspberry Pi). Map a directory or volume to `/var/lib/hdhr-mux`.
- `.deb` and `.rpm` packages and plain tarballs for amd64, arm64 and armv7, with a systemd unit.
- On the same machine as the DVR, `bind: 127.0.0.1` serves that machine only.

**Tried with:** Channels DVR (HDHomeRun emulation, and M3U8 + XMLTV), tvheadend (all 16 tuners, UDP and PID filters), VLC, `hdhomerun_config`, an LG webOS TV (DLNA). A 3-hour test with 100 simulated viewers showed no leak. Not yet tried with Plex or Jellyfin, and not on a Raspberry Pi: the arm images and packages are cross-compiled, not run.

This is a 0.99 release: it works for the author's setup and the protocol work is checked against real devices, but expect rough edges.
