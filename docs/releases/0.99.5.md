## hdhr-mux 0.99.5

Changes since 0.99.4.

**History of changes (new)**
- A **Call sign changes** button on the Lineup page opens a **Changes** page: a station's call sign or number, a channel the devices now put on another RF channel, channels added or removed, and, read from the multiplexes themselves, programmes that came or went on an RF channel and new transport stream ids. Disabled channels are watched too. Filter, chips and a download of the file.
- Kept in its own file, `changes.log` in the state directory (one JSON object per line, rotated at 4 MB); each change also appears in the log as `changes: …`.

**Logs page (new)**
- The last 4000 log lines, followed live over server-sent events (plain HTTP: no library, no WebSocket settings behind a proxy), with a filter, chips for the parts that log (`hub`, `guide`, `req`, `upstream` …), Follow, Wrap, Clear and Download. Local network only.
- `log_requests_on` limits "Log every request" to the `web`, `udp`, `tcp` or `stream` port.

**Activity page**
- The free tuners fold away (closed by default) and open into an aligned grid.
- Settings, Miscellaneous: **Show tuners as** device ID or IP address.
- A tuner another application holds without a PID filter shows as **Full multiplex** instead of every channel on it.
- The multiplexer's own device-search broadcast, heard by its own listener, is no longer logged or answered.

**Advanced tab**
- By default only the lineup's RF channel is used for a channel received on several; tick another to allow it. `auto_join_other_locations` is off by default.

**Guide**
- An unlocked guide pass whose tuner was cleared by somebody else lets go instead of looking for another tuner.

**Web interface**
- Lower buttons and filters.

**Docs and deployment**
- `docker-compose.yml` (host networking) and `docker-compose.bridge.yml`, with Compose and Portainer notes.
- The README is an overview with an index; the reference moved into `docs/`.

Everything else is as in 0.99.4. Still: no LICENSE file.
