## hdhr-mux 0.99.3

Changes since 0.99.2.

**Advanced tab (replaces Channels)**
- Shows only the channels received on more than one RF channel, with Video / First / EPG. At least one RF channel of a channel has to stay on; whether a channel exists is decided in the Lineup.
- The "unavailable" state is gone. Old choices that had every RF channel off are ignored.
- **Merged channels**: groups of channels you say carry the same programme (11.1 and 11.3, say). For the tuners they are one: a request for any member rides a stream that already carries any member, and otherwise tunes the requested channel's own place first, then the others'. Disabled members still count. Saved in `merges.json`; nothing is merged automatically.

**Lineup**
- A star column flips each channel between enabled, favourite and disabled, as on a device. It changes this multiplexer only; the devices are not told. A client doing the same (`lineup.post?favorite=+7.1`, `-7.1`, `x7.1`) has the same effect, and `lineup.json?show=found` lists disabled channels with `Enabled: 0`.
- Disabled channels are left out of the lineup, playlist and guide and are not tuned. New "Disabled" filter.

**Diagnostics**
- `log_requests_on` limits "Log every request" to some of the ports: `web`, `udp`, `tcp` (the control port) and `stream` (5004). Applies live.

**Web interface**
- Smaller corner radii, like the Channels DVR interface. "On multiple RF channels".

Everything else is as in 0.99.2. Still: no LICENSE file. The armhf (32-bit) build runs on a Raspberry Pi 4. The arm64 package installs and starts under systemd on Debian arm64 (a VM on Apple Silicon, without devices, so streaming there is untested).
